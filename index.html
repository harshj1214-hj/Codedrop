    How it works

    The file is encrypted on your phone with AES-256-GCM before it’s uploaded. The key is derived from the code (PBKDF2, 250,000 rounds) and the code is never uploaded, so the storage only holds scrambled data. The first four characters find the file; the last eight unlock it.

    The QR code and the link carry the same code, so treat them like the code itself. Files can be up to 25 MB. Share codes privately: anyone who has one can open the file until it expires. Expired files are cleared out automatically.

    Send directly connects the two phones over the internet and streams the file between them, so nothing is stored anywhere. A free public matchmaking service (PeerJS) only introduces the phones; the file itself is encrypted in transit by the phones. It needs both phones online at the same time, and a few networks block direct connections; Create code works on those. Files can be up to 100 MB.

    Send by QR animation works with no internet at all: the file travels as a stream of QR codes from this screen to the other phone’s camera. Missed frames don’t matter because each frame carries a different mix of the file (a fountain code), and the whole file is checked at the end. It isn’t encrypted, so anyone filming the screen could capture it, and it’s slow: a few KB per second.
